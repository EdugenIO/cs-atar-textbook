## Findings and fixes

- Most chapter preparation blocks lacked a direct matching activity route. Chapters now link their relevant extension-pack activities; the four audited lessons have a five-step guided route with concrete prerequisites and a changed retry. The resource hub includes these same four routes.
- Activity/student and answer pages had pack-level links but no consistent activity-specific return/revision loop. All 18 extension-pack activities now link directly to their own key, reading and matching revision topic; answer pages return to the specific activity. These controls are excluded from worksheet printing.
- Chapter SQL examples, the pathway fixtures and the activity pack use different schemas. SQL activities now name Member/Loan columns, explain that these differ, and link both the supplied database and setup script as alternatives. Paper learners can reopen the exact Activity 01 tables.
- Grouped reports were indexed under beginner SQL, and an exit question introduced LEFT JOIN without preparation in that activity. Activity 05 is now on the advanced Unit 4 route. Whole-result aggregates (pathway 04), grouped reports (10) and supporting HAVING (17) are explicit prerequisites/links. The core exit now checks missing groups using only the supplied Loan table. HAVING stays a labelled supporting extension. Student/key PDFs and download packs were regenerated.
- A loop evidence check used sum_to(...) notation although the function implementation is an optional later revisit. The core case labels now describe the sum task in plain language; runnable function examples remain available for later learning.
- Byte-sequence network practice now states its simplified sequence/acknowledgement convention and prior TCP/UDP understanding explicitly.
- Revision pages contain broad syllabus checklists as well as chapter retrieval. Handoffs now distinguish the immediate chapter question from later checklist items, preventing an activity-completion tick being presented as course mastery.

## Verification

Browser walkthroughs followed each of the four chapter routes into the exact activity, exact key and visible revision topic. A worked-example link was verified to focus its intended chapter section. All activity links and all four named worked sections have regression checks. SQL stage links are checked against actual pathway stage titles. The SQL changed-sort retry is checked against the supplied database.

The revised SQL student pages 9–10 and teacher page 5 were rendered and visually inspected: no clipped content or overlapping writing spaces. Existing pack/page-count, code/data/result, archive and print-mode tests remain in place. Offline readers and the complete library are rebuilt with the new routes.

Next validation is a real classroom trial: observe whether students can find their activity independently, keep a prediction distinct from execution, explain a correction, and retrieve the idea again later.
